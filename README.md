# Alpacala Wireless — Website

B2B website for Alpacala Wireless: wholesale SIM card distribution and activation
services for dealers, MVNOs and enterprise buyers.

Built with **Next.js 14 (App Router) + React 18**, styled with a hand-written CSS
design system. No UI framework, no runtime CSS-in-JS — the only client-side JS is
navigation, scroll reveal, animated counters, FAQ accordions and the contact form.

## Pages

| Route          | Page                                                        |
| -------------- | ----------------------------------------------------------- |
| `/`            | Home                                                        |
| `/bulk-sim`    | Bulk SIM cards — process, pricing tiers, specs, FAQ         |
| `/activation`  | Activation services — service grid, workflow, reporting     |
| `/carriers`    | Carrier partners — network cards, plan types, compliance    |
| `/partnership` | Partnership — value props, cooperation models, onboarding   |
| `/about`       | Company — story, values, compliance notes                   |
| `/contact`     | Contact — details, RFQ form, FAQ                            |

`/robots.txt` and `/sitemap.xml` are generated by `app/robots.js` and `app/sitemap.js`.

## Run locally

```bash
npm install
npm run dev     # http://localhost:3000
```

Production check:

```bash
npm run build
npm start
```

## Deploy to Vercel (free tier)

**Option A — Git import (recommended, gives automatic redeploys)**

1. Push this folder to a GitHub / GitLab / Bitbucket repository.
   ```bash
   git init && git add . && git commit -m "Alpacala Wireless site"
   git remote add origin <your-repo-url> && git push -u origin main
   ```
2. Go to <https://vercel.com/new>, sign in, and import the repository.
3. Vercel detects Next.js automatically. Leave every build setting at its default
   (Framework `Next.js`, Build Command `next build`, Output Directory `.next`).
   No environment variables are required.
4. Click **Deploy**. The site is live at `https://<project>.vercel.app` in about a minute.

**Option B — Vercel CLI**

```bash
npm i -g vercel
vercel          # preview deployment
vercel --prod   # production deployment
```

**Option C — any Node host / static export**

The site is fully static-friendly. To emit plain HTML/CSS/JS instead:

```bash
NEXT_EXPORT=1 npm run build   # writes ./out
```

Upload `out/` to any static host. Routes are exported as `bulk-sim.html` etc., so
enable pretty/clean URLs (or add rewrite rules `/bulk-sim` → `/bulk-sim.html`) —
Vercel, Netlify and GitHub Pages do this out of the box.

## Deploy URL

Once deployed, update the canonical host in two places so the sitemap and metadata
point at your real domain:

- `app/layout.js` → `metadataBase`
- `app/sitemap.js` / `app/robots.js` → `BASE`

## Notes

- Every route is statically prerendered (`○ (Static)` in the build output), so the
  free Vercel tier is more than enough — no server functions, no database.
- The build output is also verified against 390 / 430 / 768 / 1024 / 1440 px with
  zero horizontal overflow and zero console errors.
- `preview/` holds reference screenshots of the current build.

## Performance & accessibility notes

- The hero banner is delivered as WebP (63 KB) with a JPEG fallback via CSS
  `image-set()`, and preloaded with `fetchpriority="high"` so it is the first paint
  asset rather than a late CSS-side discovery.
- Carrier logos are trimmed to their artwork and served at 2× display size.
- Stats render their real values in the static HTML (no JS needed) and only count
  up once the band scrolls into view; `prefers-reduced-motion` skips the animation.
- Every interactive element has a visible `:focus-visible` ring, the header marks
  the current page with `aria-current="page"`, and a skip-link jumps to `#main`.
- `.reveal` elements are forced visible under `<noscript>` so content never
  depends on JavaScript.

## Editing content

Page copy lives in the data arrays at the top of each `app/<route>/page.js`
(`SERVICES`, `STEPS`, `TIERS`, `FAQS`, …). Change the array and the markup maps
over it — no need to touch JSX structure.

Colours, spacing and typography are CSS custom properties at the top of
`app/globals.css`:

```css
--blue-600: #2563eb;
--grad: linear-gradient(120deg, #2563eb, #22d3ee);
```
